# 面试讲解指南

## 1. 60 秒项目介绍

我做的是一个医疗票据智能识别与理赔预审项目。整体链路把职责拆成三层：OpenCV 和 PaddleOCR 负责图像处理、文字坐标与置信度；Qwen-VL 只在候选字段白名单内做结构化抽取并关联 OCR 证据；六条业务规则由 Python `Decimal` 按固定优先级计算。高优先级规则遇到缺字段、低置信或异常时会直接转人工，不会让模型或低优先级规则猜一个金额。工程上提供 FastAPI 审核接口、React 三栏复核台、乐观版本冲突、Docker 无模型 demo、CI 和公开仓库安全扫描。公开 demo 使用合成 fixture；真实 OCR/VLM adapter 已实现和测试，数据库、异步任务、对象存储与权限系统作为生产化扩展方案。

## 2. 可证据化的简历表述

只使用能在仓库代码和测试中指出证据、且你能现场解释的描述：

- 构建 OpenCV → PaddleOCR → Qwen-VL 的多模态票据抽取链路，保留 OCR bbox/置信度与原图/处理图证据，使用候选字段白名单和 Pydantic Schema 约束模型输出。
- 将 6 条理赔预审逻辑实现为固定优先级的 `Decimal` 规则引擎，区分缺失值与 `0.00`，对低置信、负数、字段不完整和金额不平衡场景转人工复核并输出完整 trace。
- 搭建 FastAPI + React 三栏审核 demo，支持字段修正后重新计算、版本冲突保护、通过/驳回和脱敏审计事件，并提供无模型 Docker 启动与 CI/公开仓库安全门禁。

不要写“已在保险公司生产落地”“准确率达到某值”“支持某并发量”或“降低成本某比例”；仓库没有这些证据。

## 3. 高频技术问答

### 为什么不是只用 OCR？

OCR 擅长文字与坐标，但不同地区票据字段别名、版式和表格关系变化大。VLM 用来理解版面并从候选集合抽取字段；OCR token 仍是证据锚点。这样既利用语义能力，又保留可核验来源。

### 为什么不让大模型直接算最终金额？

金额规则需要可重复、可测试、可审计。模型输出可能漂移，也可能受票据内提示注入影响。项目让 VLM 提取事实，用 `Decimal` handler 计算，并返回公式、输入和逐条 trace。

### 为什么用 Decimal，不用 float？

二进制浮点不能精确表示多数十进制金额。`Decimal` 能保持金额语义，并显式使用 `0.01` 容差处理票据平衡判断。

### “首条匹配”有什么风险控制？

R001 到 R006 是业务优先级。首条命中就停止；更关键的是，高优先级规则已经出现候选证据却缺字段或低置信时，返回 `NEEDS_REVIEW`，而不是继续找一条更容易命中的规则。

### 证据和置信度怎么用？

抽取结果引用 OCR 文本与 bbox。模型声称的 evidence 必须能匹配 OCR token；金额字段没有证据时会被限制置信度，随后由规则阈值决定是否转人工。页面可以从字段切换到对应证据框。

### 模型调用怎么重试？

Ollama timeout、网络传输错误和 5xx 被标记为可重试；4xx 与 Schema 错误是确定性问题，不盲目重试。各阶段异常映射为脱敏的稳定错误类型，避免把 OCR 或模型正文带进日志。

### 人工修改后如何保证规则一致？

字段修正进入标准 `FieldValue`，随后立即重新运行同一个序贯规则引擎。请求携带 `expected_version`，旧版本修改会冲突。demo 使用进程锁；生产应把版本检查迁移到数据库事务。

### 为什么模型不放 Git？

权重大、许可证和来源需要单独管理，也可能被误打进历史。仓库只定义本地目录契约和只读挂载方式；默认 demo 不下载模型，因此面试官能快速运行。

### Docker 演示证明了什么？

它证明合成审核工作流、API/UI 集成和规则逻辑可复现，不证明真实模型精度或生产部署。默认只有非 root API 与 Nginx web 两个服务，web 代理 `/api` 和 `/health`。

### 数据库、队列和权限做了吗？

没有。当前是单进程、合成 fixture、重启复位的 demo。PostgreSQL、Redis/Celery、MinIO、JWT/RBAC 是明确的下一阶段，不应在简历中写成已实现。

## 4. 现场演示顺序

1. `docker compose up --build`，打开三栏审核台并说明“合成数据”。
2. 展示一个字段的 OCR evidence 和置信度。
3. 修改字段，观察版本增长与规则 trace 重新计算。
4. 解释 R001→R006 首条匹配和 `NEEDS_REVIEW` 不降级。
5. 打开 adapter、规则测试与安全扫描脚本，说明真实链路和公开边界。

## 5. 面试官可继续追问的改进方向

- PostgreSQL 作为案件/审核事实来源，事务内做 optimistic locking。
- Celery 任务幂等键、分阶段重试、失败队列和处理耗时指标。
- MinIO 私有对象、短期签名 URL、数据保留与删除策略。
- JWT/RBAC、敏感字段遮罩、完整值访问审计。
- 私有标注集上的字段 F1、金额 exact match、规则选择准确率和人工审核率。
